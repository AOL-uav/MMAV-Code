1. What OpenFOAM is, and is not

OpenFOAM has no user interface. It is a collection of command-line programs. Each program reads a folder of plain text files (the case) and writes new folders of numbers. You edit the text with any editor and run the programs from a terminal.

CFD (computational fluid dynamics) means computing the flow of air or water on a computer instead of in a wind tunnel. ParaView is a separate program that draws the results. It is not part of OpenFOAM.

What is installed on this machine (checked 2026-10-13)
  • OpenFOAM v2606 (the openfoam.com / ESI version) is installed in the WSL distro MMAV-CFD, with its tutorials and source code, plus gmsh, Python 3, numpy and matplotlib.
  • ParaView 5.12.0 is installed on Windows (installed with winget: winget install --id Kitware.ParaView -e) in C:\Program Files\ParaView 5.12.0. Start it from the Start menu. Its command-line tools pvpython.exe and pvbatch.exe are in the bin folder there. It is NOT installed inside the Linux distro; it does not need to be.
  • Tested on this machine: ParaView on Windows opens the case files directly through the \\wsl.localhost\MMAV-CFD\... path and renders off-screen to PNG files (all pictures in section 8 were made that way). The ParaView window was started once and answered normally; the menu clicks below were not clicked through by me, they follow the same filters I ran from a script.
  • The old wrapper paraFoam in the distro is not used and not needed.

2. How to get in

WSL (Windows Subsystem for Linux) runs a real Linux system inside Windows. A distro is one installed Linux system. OpenFOAM lives in the distro called MMAV-CFD.

Open a Linux shell inside it, from PowerShell:

wsl -d MMAV-CFD

You land as the user cfd in /home/cfd. The OpenFOAM commands are already available because ~/.bashrc loads them. All practice cases are in ~/run/learn/. The sweep cases are in ~/run/vp_*.

To see the files from Windows Explorer, paste this in the address bar:

\\wsl.localhost\MMAV-CFD\home\cfd\run
Never use the QuadFlightStack distro for this. It belongs to another project. Always write wsl -d MMAV-CFD with the name; do not type plain wsl, because that opens the default distro, and the default is QuadFlightStack.

Do not keep case data on OneDrive. Cases live in the distro's Linux home.

4. The maths, built up gently

(a) The equations: mass and momentum

The fluid is incompressible: its density does not change. Air at these speeds behaves that way. The velocity u is a vector and p is pressure. Two laws govern the flow.

Conservation of mass. What flows into any small volume flows out; nothing piles up. For incompressible flow the divergence of velocity is zero:

∇·u = 0

Conservation of momentum (Newton's second law for fluid; with the Navier-Stokes equations):

∂u/∂t  +  ∇·(u u)  =  −∇p  +  ν ∇²u
  • ∂u/∂t: the unsteady term. How fast the velocity at a point changes with time.
  • ∇·(u u): the convection term. Momentum is carried along by the flow itself. This term makes the equations nonlinear.
  • −∇p: the pressure-gradient term. Fluid is pushed from high pressure toward low pressure.
  • ν ∇²u: viscous diffusion. Friction smooths velocity differences. ν (nu) is the kinematic viscosity.

In these equations p means pressure divided by density (the solvers use this kinematic pressure, units m²/s², as seen in 0/p: dimensions [0 2 -2 0 0 0 0]).

The Reynolds number compares the two big terms, convection and viscous diffusion:

Re = U L / ν   (speed × length ÷ kinematic viscosity)

Small Re: viscosity wins, the flow is smooth and orderly. Large Re: convection wins, the flow can become unsteady and turbulent. The cavity has Re = 1 × 0.1 / 0.01 = 10. The toy plate has Re = 1000. The real validation plate has Re = 60,000 (chord 88.9 mm).

(b) The finite-volume idea

Nobody can solve the equations for a whole wing at once. So the space is cut into small cells (the mesh). Each cell stores one value of each field. Then for each cell you integrate the equation over the cell volume. The Gauss theorem turns an integral of a divergence over a volume into a sum over the cell's faces:

∫V ∇·F dV  =  ∮S F·n dS  ≈  Σfaces Ff·Sf

Sf is the face area vector (area times the outward normal). So the equation for a cell becomes: the change inside = what comes through the faces. The flux leaving one cell is exactly the flux entering its neighbour, so mass and momentum are conserved by construction. That is why the method is called finite volume.

(c) What fvSchemes chooses

The balance needs the field value at a face, but only cell-centre values are stored. system/fvSchemes says how to estimate it, term by term. The real cavity file:

01_cavity/system/fvSchemes
ddtSchemes
{
    default         Euler;
}

gradSchemes
{
    default         Gauss linear;
    grad(p)         Gauss linear;
}

divSchemes
{
    default         none;
    div(phi,U)      Gauss linear;
}

laplacianSchemes
{
    default         Gauss linear orthogonal;
}

interpolationSchemes
{
    default         linear;
}

snGradSchemes
{
    default         orthogonal;
}
  • ddtSchemes: how ∂/∂t is approximated. Euler uses the current and previous time step (first-order). The validation case uses backward, which uses two previous levels (second-order).
  • gradSchemes: how a gradient is computed from cell values. Gauss linear is the Gauss theorem above with face values averaged linearly.
  • divSchemes: the convection term. This is the important choice. Linear interpolation is second-order accurate but can overshoot and wiggle near sharp changes. Upwind takes the value from the cell the flow comes from; it never wiggles but smears sharp features (first-order). Limited schemes mix the two: linear where the solution is smooth, upwind-like where it would wiggle.
  • laplacianSchemes, snGradSchemes: the viscous term and face-normal gradients. corrected adds a fix for cells that are not squarely aligned (non-orthogonal).

The validation case uses a limited scheme, taken from its own fvSchemes:

vp_a4_coarse/system/fvSchemes
{
    version 2.0;
    format ascii;
    class dictionary;
    object fvSchemes;
}
ddtSchemes { default backward; }
gradSchemes { default Gauss linear; }
divSchemes
{
  default none;
  div(phi,U) Gauss limitedLinearV 1;
  div((nuEff*dev2(T(grad(U))))) Gauss linear;
}
laplacianSchemes { default Gauss linear corrected; }
interpolationSchemes { default linear; }

wallDist { method meshWave; }

(d) The pressure-velocity problem

In incompressible flow there is no equation for pressure. Pressure is not a thermodynamic variable here. It is whatever field makes the velocity satisfy ∇·u = 0. So solvers use a loop (PISO: pressure-implicit with splitting of operators; PIMPLE is PISO with an optional outer loop). Here is the real loop, copied verbatim from the installed icoFoam.C (the { ... } braces are part of the file):

    while (runTime.loop())
    {
        Info<< "Time = " << runTime.timeName() << nl << endl;

        #include "CourantNo.H"

        // Momentum predictor

        fvVectorMatrix UEqn
        (
            fvm::ddt(U)
          + fvm::div(phi, U)
          - fvm::laplacian(nu, U)
        );

        if (piso.momentumPredictor())
        {
            solve(UEqn == -fvc::grad(p));
        }

        // --- PISO loop
        while (piso.correct())
        {
            volScalarField rAU(1.0/UEqn.A());
            volVectorField HbyA(constrainHbyA(rAU*UEqn.H(), U, p));
            surfaceScalarField phiHbyA
            (
                "phiHbyA",
                fvc::flux(HbyA)
              + fvc::interpolate(rAU)*fvc::ddtCorr(U, phi)
            );

            adjustPhi(phiHbyA, U, p);

            // Update the pressure BCs to ensure flux consistency
            constrainPressure(p, U, phiHbyA, rAU);

            // Non-orthogonal pressure corrector loop
            while (piso.correctNonOrthogonal())
            {
                // Pressure corrector

                fvScalarMatrix pEqn
                (
                    fvm::laplacian(rAU, p) == fvc::div(phiHbyA)
                );

                pEqn.setReference(pRefCell, pRefValue);

                pEqn.solve(p.select(piso.finalInnerIter()));

                if (piso.finalNonOrthogonalIter())
                {
                    phi = phiHbyA - pEqn.flux();
                }
            }

            #include "continuityErrs.H"

            U = HbyA - rAU*fvc::grad(p);
            U.correctBoundaryConditions();
        }

        runTime.write();

In words: (1) guess the new velocity using the old pressure; that guess does not conserve mass. (2) Solve one pressure equation whose answer is the pressure that would fix that. (3) Use the pressure to correct velocity and the face fluxes phi so that mass is conserved. Repeat a couple of times (nCorrectors) because the correction changes the momentum balance slightly. The log lines "time step continuity errors" report how well step (3) worked. phi is the volume flux through each face, one number per face.

(e) What fvSolution chooses

Each equation above, written for every cell at once, is a very large sparse linear system (millions of unknowns, each linked only to its few neighbours). It is solved iteratively: guess, improve, repeat until good enough. system/fvSolution picks the method and when to stop. The cavity file:

01_cavity/system/fvSolution
solvers
{
    p
    {
        solver          PCG;
        preconditioner  DIC;
        tolerance       1e-06;
        relTol          0.05;
    }

    pFinal
    {
        $p;
        relTol          0;
    }

    U
    {
        solver          smoothSolver;
        smoother        symGaussSeidel;
        tolerance       1e-05;
        relTol          0;
    }
}

PISO
{
    nCorrectors     2;
    nNonOrthogonalCorrectors 0;
    pRefCell        0;
    pRefValue       0;
}
  • The residual is a normalised measure of how far the current guess is from satisfying the equation. Zero = perfect. The solver prints it twice: Initial residual (before this solve) and Final residual (after).
  • tolerance 1e-06: stop when the residual falls below this. relTol 0.05: or stop when it has fallen to 5 % of its starting value. relTol 0 means demand the full tolerance.
  • pFinal is the pressure solve on the last corrector pass of a step, usually tighter. $p; copies the settings of p.
  • PISO { nCorrectors 2; }: two pressure passes per step, which is why each time step in the log has two Solving for p lines.

(f) Time step and Courant number

The flow is advanced in small time steps Δt. If Δt is too large for the cell size, the numbers go wrong and the run blows up (values grow without limit and the program stops). The warning number is the Courant number. In one dimension it is

Co = u Δt / Δx

speed times time step divided by cell size: the fraction of a cell the fluid crosses in one step. OpenFOAM computes it per cell from the face fluxes. The installed CourantNo.H says:

scalar CoNum = 0.0;
scalar meanCoNum = 0.0;

{
    scalarField sumPhi
    (
        fvc::surfaceSum(mag(phi))().primitiveField()
    );

    CoNum = 0.5*gMax(sumPhi/mesh.V().field())*runTime.deltaTValue();

    meanCoNum =
        0.5*(gSum(sumPhi)/gSum(mesh.V().field()))*runTime.deltaTValue();
}

so "max" in the log is the worst cell and "mean" the average.

With adjustTimeStep yes the solver chooses Δt so the largest Courant number stays at maxCo. The toy case uses 1. The sweep cases use 1.5, which is inside the 1 to 2 range asked for the validation runs; they ran stable at that value. A larger maxCo means fewer, bigger steps and so a cheaper run, but with less margin before blow-up. The log of the real run confirms the limit is held: Courant Number mean: 0.0149 max: 1.5001. Small cells and fast flow near the plate's edges are what limit the step (an inference from the cell sizes, not a measurement).

(h) Laminar or turbulence model

At high Reynolds number flow becomes turbulent: many small swirls. Resolving them all needs enormous meshes, so engineers often add a turbulence model that stands in for the swirls. A laminar run adds no model and solves the equations as written.

The validation case is run laminar. What cfd/VALIDATION_SCOPING.md records about that choice, quoted:

"pimpleFoam, laminar (no turbulence model), nu = 1.6667e-5."
"The coarse solution is steady: the leading-edge bubble and transition are not resolved (LE radius 0.004 c, cell 0.008 c). The medium mesh develops unsteadiness the coarse mesh damped, so the coarse 'steady state' is partly numerical."

That file states the choice but gives no longer reason, and none is added here. The real settings:

6. Lesson 2: a 2D flat plate

This is a teaching toy. The mesh is coarse, the Reynolds number (1000) is far from the real case (60,000), the domain is small, and no claim is made about accuracy. Use it to learn the workflow and to see how the settings change the result. Do not quote its numbers.

A thin plate, chord 1, 4 % thick, flat along x. The free stream is tilted up by 4°, so the plate sees 4° angle of attack. Laminar, Re = 1000, about 11,500 cells, one CPU core, about 85 s. Files are in ~/run/learn/02_plate2d, and every entry in them has a one-line comment.

{
    farfield
    {
        type            freestreamVelocity;   // far from the plate: if air is entering, impose the free stream; if leaving, let it go. Lets one patch act as both inlet and outlet
        freestreamValue $internalField;       // the free-stream value to use: copy of the internalField line above
    }

    {

Three experiments

First copy the case so the original stays intact: cp -r ~/run/learn/02_plate2d ~/run/learn/03_mine; cd ~/run/learn/03_mine; ./Allclean. Run each change separately, compare coefficient.dat with the baseline, and write down what you see.

  1. Change the angle. In 0/U change the free-stream vector to (cos α, sin α, 0) with a new α, and in system/controlDict change liftDir and dragDir to match (lift is perpendicular to the free stream, drag along it). Look at: does CL rise as you expect, and does the wake (speed.png) change shape? What happens if you forget to update liftDir?
  2. Halve the mesh spacing. In system/blockMeshDict double every cell count (30 60 50 → 60 120 100, and so on for the other blocks; keep shared edges equal). That is about four times the cells, and the time step also shrinks, so expect a much longer run. Look at: how much do CL, CD and CM move? If they barely move, the first mesh was already adequate for this question; if they move a lot, it was not.
  3. Switch to upwind. In system/fvSchemes change div(phi,U) Gauss limitedLinearV 1; to div(phi,U) Gauss upwind;. Look at: do the forces change? Is the wake in speed.png smoother or more smeared? This is the accuracy-versus-wiggles trade-off from section 4c.

7. How the real validation case differs from the toy

  • 3D half model. The wing is 3D: a plate of aspect ratio 3 with a symmetry plane at its root, so only half is meshed (the sym patch above).
  • snappyHexMesh. Instead of hand-made blocks, a coarse background box mesh is made with blockMesh, then snappyHexMesh refines it around a surface file of the plate (an STL), cuts the plate out, and adds 5 thin layers of cells on the surface. 8. Looking at results

ParaView is the program that draws the numbers OpenFOAM writes. Version 5.12.0 is installed on Windows. It reads your case folder directly; the case does not need to be on a Windows drive.

Order matters. ParaView can only show what the solver has written. Run the case first (blockMesh and the solver, or ./Allrun), then open it. The practice cases are left in the un-run state on purpose, so you do this yourself. case.foam is an empty marker file; ParaView opens it and then reads the time folders next to it.

Click by click

  1. Run a case in the distro, e.g. cd ~/run/learn/02_plate2d; ./Allrun (about 85 s).
  2. Start ParaView from the Start menu: ParaView 5.12.0.
  3. File → Open. In the "File name" box paste \\wsl.localhost\MMAV-CFD\home\cfd\run\learn\02_plate2d\case.foam and press Open. (Tested in a script: the OpenFOAM reader reads this path fine.) If ParaView asks which reader, choose OpenFOAM.
  4. In the Properties panel (left): under Mesh Regions keep internalMesh ticked (tick patch/plate too if you want the plate surface on its own). Under Cell Arrays tick U and p. Click the green Apply button. Nothing is drawn until you press Apply.
  5. Choose what to colour by. In the toolbar, the dropdown that says Solid Color lists the fields: choose U and then Magnitude (speed), or p (pressure). Cell data is one flat colour per cell, so the picture looks blocky; that is the mesh (the cavity picture below is like that).
  6. Smooth colours (optional). Filters → Alphabetical → Cell Data to Point Data, Apply, and colour that instead. The plate pictures below use it.
  7. Time. The toolbar has VCR-style buttons and a time box. The reader does not list time 0 by default (a setting called Skip Zero Time), so the first time you see is the first saved folder: 0.1 for the cavity, 5 for the plate (checked: those were the times the reader reported). Click Last Frame to jump to the final saved time (0.5 and 20).
  8. Rescale colours. Click Rescale to Data Range (next to the colour dropdown) to fit the colours to the current numbers, or Rescale to Custom Range and type a fixed range, e.g. −0.4 to 0.4 for pressure. A fixed range lets you compare two pictures fairly.
  9. 2D view. For these flat cases click the 2D button in the view toolbar, and set the view direction to look along z, so you face the plane.
  10. Slice (for a 3D case such as the real wing). Filters → Alphabetical → Slice. Set Origin and Normal (e.g. normal along y for a cut along the chord at a given span position) and Apply. Colour the slice by U.
  11. Streamlines. Filters → Alphabetical → Stream Tracer. Vectors = U. Seed Type = Line: give two end points (for the plate: x = −1.5, from y = −0.6 to 0.8) and a Resolution (40 lines). Apply. Glyph (same Filters menu) draws arrows instead.
  12. Save a picture. File → Save Screenshot, pick a resolution, OK.

9. Common mistakes and how to recognise them

Blow-up from too large a time step
Typical signs: the Courant number climbing and the residuals growing, then a crash. Seen for real while setting up the validation case: starting the plate from uniform flow at deltaT 2e-3 crashed the first step; the fix was starting at deltaT 1e-5 with adjustTimeStep yes, so the step grows by itself. Fix: smaller start step or smaller maxCo.
Forgetting to load the environment
Symptom: blockMesh: command not found. In an interactive wsl -d MMAV-CFD shell it is loaded for you. Inside a script run by other tools, add source /usr/lib/openfoam/openfoam2606/etc/bashrc first. During setup, a command started non-interactively did not see OpenFOAM until this line was used.
Wrong or missing file or patch names
Two real examples from this machine. (1) A solver crashed at once with cannot find file ".../constant/turbulenceProperties": in v2606 the file is called turbulenceProperties; the error message names the exact file wanted. (2) When the plate patch was missing from the mesh, forceCoeffs ran but every coefficient was exactly 0 and the log had a warning from polyBoundaryMesh::patchSet. Patch names in 0/U, 0/p, controlDict must equal the names in the mesh (constant/polyMesh/boundary).
Wrong units or missing semicolon
Gives a parse error naming the file and line. Read the first lines after FOAM FATAL.
Running a second parallel job on top of the sweep
While the sweep ran (/home/cfd/run/sweep/, now finished) it used all 12 physical cores; any batch run does the same. A second heavy job shares those cores and slows both, so check what is running first (pgrep -a pimpleFoam). Small serial practice runs like the toy cases are fine: they use one core, and were run with nice -n 19 (lowest priority). Do not edit or delete anything under vp_* or sweep/; they are the validation results.
Continuing from stale results
Old time folders and processor* folders from an earlier run make a rerun start from them or fail to decompose. Clean first (./Allclean in the toy cases).

Glossary

boundary condition
Rule that fixes a field's value or gradient on a boundary patch.
cell
One small volume of the mesh; stores one value per field.
Courant number
Fraction of a cell the fluid crosses in one time step.
CL, CD, CM
Lift, drag and pitching-moment coefficients: force or moment divided by dynamic pressure times reference area (times length for moment).
convection
Transport of a quantity by the flow itself.
diffusion (viscous)
Smoothing of velocity differences by friction.
face
The flat side shared by two cells (or a cell and the boundary).
flux (phi)
Volume of fluid crossing a face per second.
incompressible
Density treated as constant.
laminar
Smooth, orderly flow; also the choice to run without a turbulence model.
mesh
All cells together.
MPI / rank
MPI is the library for running one job on several cores; a rank is one of those processes.
non-orthogonality
How far a face is from being square-on to the line between its two cell centres.
patch
A named group of boundary faces.
PISO / PIMPLE
The predict-solve pressure-correct loops used for incompressible flow.
residual
Normalised measure of how badly an equation is still unsatisfied.
Reynolds number
U L / ν: ratio of convection to viscous effects.
time step
The jump in simulated time between successive solutions.
turbulence model
Extra equations that stand in for small unresolved swirls.
y+
Distance of the first cell centre from a wall, in wall units; printed at the end of the real log (average 2.77 at the plate).
