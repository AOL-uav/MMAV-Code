# MMAV Tail-Trim Clean Routine

This cleaned package keeps the reusable workflow for the fuselage-attached tail trim study:

1. **Component-wise modeling**
   - Coarse mass components: fuselage, wing, optional curled-tail mass.
   - Panelized aerodynamic geometry: optimized `opt_0615` wing and fuselage-attached curled tail.
   - One shared body/build frame:
     - `x_B` aft
     - `y_B` right
     - `z_B` up
     - origin at fuselage nose centerline
   - Active CG can be prescribed directly as `[x y z]` in body-frame millimeters.

2. **Trim analysis**
   - Uses the nonlinear VLM/XFOIL-polar solver from `opt_0615` for the main wing.
   - Includes both:
     - fixed-speed alpha-sweep diagnostic;
     - nonlinear algebraic EOM steady-glide trim solve where `V`, `alpha`, and glide angle are solved.

3. **Free fuselage-attached tail design**
   - Tail is defined by physical dimensions:
     - attachment point
     - span
     - arc chord
     - curl angle
     - incidence angle
   - Optional gap enforcement keeps the centerline tail inside the exposed-wing gap.
   - Tail design search can use either the fixed-speed diagnostic or the EOM-based trim solver.

## Single source of configuration

Edit this file first:

```matlab
MMAV_USER_CONFIG.m
```

All RUN scripts read the same shared configuration. `RUN_01_component_model` does **not** save a hidden selected state for `RUN_02` or `RUN_03`. Instead, every script independently calls `MMAV_USER_CONFIG.m`, so the selected CG, tail geometry, polar file, aero mode, and search grid are consistent and reproducible.

Important central settings:

```matlab
U.active_cg_B_mm = [42 0 0];

U.tail.aero_mode = 'drag_only';      % recommended physical model
U.tail.origin_B_mm = [70 0 5];
U.tail.span_mm = 74;
U.tail.arc_chord_mm = 110;
U.tail.curl_deg = 35;
U.tail.incidence_deg = 0;
U.tail.drag_CD = 1.20;
U.tail.drag_area_model = 'projected_normal';
```

## Tail aerodynamic modes

The default and recommended model is:

```matlab
U.tail.aero_mode = 'drag_only';
```

In this mode:

- the tail is **not** included in the VLM lifting-surface solve;
- VLM is run for the optimized wing only;
- the curled tail is treated as a drag-producing fuselage-attached sheet;
- each tail panel gets a drag force along the relative-wind drag direction;
- the tail moment is generated by the drag force acting at the tail panel centroids.

The diagnostic/legacy option is:

```matlab
U.tail.aero_mode = 'vlm_lifting_surface';
```

This includes the curled tail in the coupled VLM solve. It can overestimate authority for a fuselage-attached tail and should not be the default physical model for this design concept.


The recommended main workflow is:

```text
Edit MMAV_USER_CONFIG -> RUN_01 -> RUN_02B -> RUN_03B
```

`RUN_02_trim_analysis` and `RUN_03_tail_design_search` remain useful diagnostics because they show how the aerodynamic curves behave at a chosen speed. The more conventional trim answer comes from `RUN_02B_eom_glide_trim
RUN_02C_fixed_speed_velocity_scan`.

## EOM trim formulation

The EOM-based solver uses the reduced symmetric unpowered glide trim equations:

```text
unknowns z = [V_mps, alpha_deg, gamma_deg]

gamma > 0 means descending glide angle.

L(V,alpha) - W*cos(gamma) = 0
D(V,alpha) - W*sin(gamma) = 0
Cm_y(V,alpha)             = 0
```

The corresponding conventional longitudinal state interpretation is:

```text
u_forward = V*cos(alpha)
w_down    = V*sin(alpha)
theta     = alpha - gamma
beta = 0, phi = 0, p = q = r = 0
```

So `alpha` is solved as part of the steady-glide trim state, not merely prescribed by a sweep.

## Polar file

For final results, set the polar file explicitly in `MMAV_USER_CONFIG.m`:

```matlab
U.polar_file = fullfile('C:','path','to','NACA_0008.dat');
```

If `U.polar_file = ''`, the routine auto-searches common filenames. If no file is found, it uses a synthetic fallback polar only so the scripts can still run. Do not use synthetic-polar results as final design evidence.

## Important modeling assumptions

- The active CG is the point used for moment aggregation. It can be independent of the coarse component mass CG.
- In the default `drag_only` mode, the curled tail creates no VLM lift. It creates drag based on projected panel area and relative-wind direction.
- Fuselage force is modeled as flat-plate drag applied at its pressure-center point.
- Tail/wing overlap is checked in `y_B`; zero overlap is required for clean geometry.
- The `vlm_lifting_surface` tail mode is retained only for comparison/debugging.


## Velocity scan note

`RUN_02B_eom_glide_trim` solves velocity as an unknown. It is not a velocity sweep. Use `RUN_02C_fixed_speed_velocity_scan` to fix velocity, solve alpha/gamma force balance, and inspect the remaining `Cm_y` residual across speeds.

## Controlled trim addition

`RUN_02D_controlled_trim_at_speed.m` adds a conventional fixed-speed trim solve with controls.

Solved variables:

```matlab
x = [alpha_deg, gamma_deg, wing_collective_deg, tail_curl_delta_deg]
```

Residual equations:

```matlab
R_lift = L/W - cos(gamma)
R_drag = D/W - sin(gamma)
R_Cm   = Cm_y
```

The wing collective command is applied equally to the right and left wing incidence angles.  The aero layer also supports right/left wing incidence and differential incidence, but `RUN_02D` keeps differential at zero because it is a symmetric longitudinal trim solve, not a full 6-DOF roll/yaw trim.

The tail deformation command is modeled as a change in tail curl angle:

```matlab
tail_curl_total = baseline_tail_curl + tail_curl_delta
```

Edit the default controlled trim settings in `MMAV_USER_CONFIG.m` under **Control trim settings**.
